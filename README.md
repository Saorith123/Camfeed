# CamFeed Security Update — ការណែនាំដាក់ឱ្យប្រើ

## អ្វីដែលបានកែ
1. **ពាក្យសម្ងាត់ត្រូវបាន hash** (scrypt) មិនរក្សាទុកជាអត្ថបទធម្មតាទៀតទេ។ ពាក្យសម្ងាត់ចាស់ត្រូវបានប្តូរដោយស្វ័យប្រវត្តិពេលអ្នកប្រើចូលលើកក្រោយ។
2. **Server លែងផ្ញើ password ត្រឡប់ទៅ browser** (រាល់ JSON ត្រូវបានលុប field `password` ចេញ)។
3. **Token (JWT)**៖ ទាំង Like, Comment, សារ, Follow, Admin... ឥឡូវ server ប្រើអត្តសញ្ញាណពី token មិនមែនពី email ដែល browser ផ្ញើទេ។ ការបន្លំជាអ្នកផ្សេងលែងអាចធ្វើបាន។
4. **ការពារការទាយពាក្យសម្ងាត់**៖ ខុស 8 ដង → រង់ចាំ 15 នាទី។
5. **Admin PIN**៖ លែងមានតម្លៃលំនាំដើមក្នុងកូដ ត្រូវកំណត់ `ADMIN_SECRET_KEY`។
6. ទំព័រ **Settings** (ប្តូរឈ្មោះ / ពាក្យសម្ងាត់ / លុបគណនី) ដំណើរការពិតប្រាកដ (មុននេះ server មិនមាន route ទាំងនេះទេ)។ លុបគណនីលុបទិន្នន័យទាំងអស់ និងឯកសារ R2។
7. ប្តូរពាក្យសម្ងាត់ ឬ Ban → ឧបករណ៍ផ្សេងទៀតត្រូវចូលម្តងទៀតភ្លាម។

## ជំហានដាក់ឱ្យប្រើ
1. **Render → Environment** បន្ថែម៖
   - `JWT_SECRET` = អក្សរចៃដន្យវែង (≥ 32 តួ)
   - `ADMIN_SECRET_KEY` = PIN របស់ Admin
2. ជំនួស `server.js` ហើយបន្ថែម `auth.js` និង `migrate-passwords.js` ក្នុងថតដូចគ្នា (មិនត្រូវការ `npm install` អ្វីថ្មីទេ)។
3. ដាក់ `public/auth-client.js` ហើយក្នុងទំព័រ HTML ទាំង 10 (admin, feed, friends, index, messages, monetization, profile, settings, upload, videos) បន្ថែមមួយបន្ទាត់ភ្លាមក្រោម `<head>`៖
   `<script src="auth-client.js"></script>`
   (ឬជំនួសឯកសារ HTML ទាំងមូលដោយឯកសារក្នុង zip)
4. Deploy។ **អ្នកប្រើទាំងអស់ត្រូវចូលម្តងទៀត 1 ដង** (ធម្មតា)។
5. បន្ទាប់ពី deploy រួច រត់ម្តងគត់៖ `node migrate-passwords.js` (ដើម្បី hash គណនីដែលមិនទាន់ចូល)។

## សាកល្បងមុន (សំខាន់)
ខ្ញុំបានសាកល្បង auth.js និង auth-client.js ដោយស្វ័យប្រវត្តិ ប៉ុន្តែ **មិនទាន់បានរត់ server ទាំងមូលជាមួយ database របស់អ្នកទេ**។ សូមសាកល្បង៖ ចុះឈ្មោះថ្មី, ចូល, បង្ហោះ, Like/Comment, ផ្ញើសារ, ផ្ទុកវីដេអូ, Settings, Admin។

## ត្រឡប់ក្រោយ (rollback)
រក្សា `server.js` ចាស់ទុក។ បើមានបញ្ហា ជំនួសមកវិញ។ ប៉ុន្តែបន្ទាប់ពីរត់ `migrate-passwords.js` ហើយ server ចាស់នឹងចូលមិនបាន (password ត្រូវបាន hash) ដូច្នេះសាកល្បងឱ្យច្បាស់មុនរត់វា។

## មិនទាន់កែ (ជំហានបន្ទាប់)
- XSS៖ escape អត្ថបទអ្នកប្រើក្នុង `innerHTML` (imageModal.js, notification.js, feed...)
- `monetization.html` ហៅ `/api/monetization/*` ដែលមិនមានក្នុង server.js
- Admin លុបអ្នកប្រើមិនទាន់លុប comments/likes/messages ជាប់ទាក់ទង
- `ssl: { rejectUnauthorized: false }` និង `ffmpeg-static` ក្នុង package.json

## 🛡️ ការការពារការបង្កើតគណនីក្លែងក្លាយ (CAPTCHA + កំណត់ចំនួន)

**ឯកសារត្រូវជំនួស៖** `server.js`, `auth.js`, `public/index.html`

**ជំហានបើក CAPTCHA (Cloudflare Turnstile, ឥតគិតថ្លៃ)**
1. Cloudflare Dashboard → **Turnstile** → **Add widget**
2. Hostname៖ ដាក់ដែនរបស់អ្នក (ឧ. `camfeedkh.com` និងដែន `xxxx.onrender.com` ដែលអ្នកកំពុងប្រើ) ; Widget mode៖ **Managed**
3. ទទួលបាន 2 សោ៖
   - **Site Key** (សាធារណៈ) → បើក `public/index.html` ស្វែងរក `PASTE_YOUR_TURNSTILE_SITE_KEY_HERE` ហើយជំនួសដោយ Site Key
   - **Secret Key** (សម្ងាត់) → Render → Environment → `TURNSTILE_SECRET_KEY`
4. Deploy ហើយសាកល្បងចុះឈ្មោះ៖ ត្រូវមានប្រអប់ "Verify you are human" នៅជំហានទី 2

> ⚠️ ប្រសិនបើអ្នកមិនទាន់ដាក់សោទាំងពីរ ការចុះឈ្មោះនៅតែដំណើរការ (CAPTCHA មិនទាន់បើក) ដូច្នេះកុំភ្លេចដាក់ពួកវា។

**កំណត់ចំនួនចុះឈ្មោះ**
- លំនាំដើម៖ **10 គណនី / ម៉ោង / IP** (ឧបករណ៍ទូរស័ព្ទជាច្រើនក្នុងកម្ពុជាចែករំលែក IP តែមួយ ដូច្នេះមិនដាក់ទាបពេក)
- កែបានដោយ Environment `REGISTER_MAX_PER_HOUR`

**ជំហានបន្ទាប់ដែលណែនាំ៖** លេខកូដផ្ទៀងផ្ទាត់ក្នុង email (ត្រូវការសេវាផ្ញើ email)។

## 🗑️ លុបទិន្នន័យពេញលេញ (ជៀសវាងពេញទំហំផ្ទុក)

**ឯកសារត្រូវដាក់៖** `server.js` (ជំនួស) និង **`cleanup.js` (ថ្មី, ដាក់ក្នុងថតដូច server.js)**

**ពេលលុប អ្វីខ្លះត្រូវបានលុបចោលទាំងស្រុង**
| សកម្មភាព | អ្វីដែលត្រូវលុប |
|---|---|
| អ្នកប្រើលុបប្រកាស / Admin លុបប្រកាស | ប្រកាស, Share, Comment, Like, ចំនួនមើល, ការជូនដំណឹង + **រូប/វីដេអូក្នុង R2 (ឬ Cloudinary)** |
| លុប Comment | Comment នោះ, Reply ទាំងអស់, Like របស់ Comment, ការជូនដំណឹង |
| ផ្ញើរូប/សំឡេងក្នុង Chat រួចលុបសារ | សារ + **ឯកសារក្នុងឃ្លាំង** |
| ប្តូររូប Profile / Cover | **រូបចាស់ត្រូវលុបចេញពី R2** |
| អ្នកប្រើលុបគណនី (Settings) ឬ Admin លុបអ្នកប្រើ | ប្រកាសទាំងអស់, **វីដេអូខ្លី + thumbnail**, Comment, Like, Follow, Block, ការជូនដំណឹង, ប្រវត្តិមើលវីដេអូ, **ការសន្ទនាឆាតទាំងពីរភាគី + ឯកសារក្នុងឆាត**, រូប Profile/Cover + ឯកសារទាំងអស់ក្នុង R2/Cloudinary |

**ច្បាប់សុវត្ថិភាព៖**
- ឯកសារត្រូវលុបចេញពីឃ្លាំងតែនៅពេលគ្មានជួរណាក្នុង database ប្រើវាទៀត (ឧ. រូបតែមួយប្រើជាទាំងប្រកាស និង Profile)
- ការលុបគណនីធ្វើក្នុង transaction បើមានកំហុសកណ្តាលទី គ្មានអ្វីត្រូវលុបពាក់កណ្តាល
- ឯកសារត្រូវលុបចេញពីឃ្លាំងបន្ទាប់ពី database លុបរួចជោគជ័យ

**ត្រូវដឹង**
- ការសន្ទនាឆាតនឹងបាត់ **ទាំងអ្នកទទួល** ផងដែរ (ជាការលុបពិតប្រាកដ)
- ឯកសារដែលក្លាយជាកាកសំណល់មុនពេលកែនេះ (ឧ. ពី Admin លុបអ្នកប្រើជាមុន) មិនទាន់ត្រូវសម្អាតទេ។ អាចធ្វើស្គ្រីបសម្អាតជាបន្ទាប់បើចាំបាច់
- មិនទាន់បានសាកល្បងលើ database ពិតរបស់អ្នក សូមសាកល្បងដោយគណនីសាកល្បង៖ បង្ហោះវីដេអូ → មើលក្នុង Cloudflare R2 → Objects ថាមានឯកសារ → លុបប្រកាស → ឯកសារត្រូវបាត់

> **Cloudinary**៖ `server.js` លែងប្រើ Cloudinary ទៀតហើយ (មិនត្រូវការ `cloudinary.js` ឬសោ CLOUDINARY_* ទេ)។ ឯកសារ `cloudinary.js` និងកញ្ចប់ `cloudinary`, `multer-storage-cloudinary` នៅក្នុង package.json មិនបង្កបញ្ហាទេ អាចទុកដូច្នេះ។

## 🎬 វីដេអូរលូន (Feed + Profile) និងទំហំវីដេអូតូចជាង

**ឯកសារត្រូវដាក់ទាំងអស់ក្នុងថត `public/`**
- ជំនួស៖ `feed.html`, `profile.html`, `upload.html`
- ថ្មី៖ `mp4-faststart.js`, `smooth-video.js`

**មូលហេតុដែលវីដេអូវិល/ងងឹត (បានរកឃើញក្នុងកូដ)**
1. ផ្ទៃខាងក្រោយ placeholder ជាពណ៌ខ្មៅ/ងងឹត ហើយមិនមានរូបទី 1 ត្រៀម (បំណែក `#t=` ត្រូវបានលុបចោល)
2. Feed ទុកតែវីដេអូ 2 (កំពុងមើល + បន្ទាប់) ក្រៅពីនោះលុបចោលភ្លាម ដូច្នេះអូសត្រឡប់ក្រោយត្រូវផ្ទុកថ្មីទាំងអស់ ហើយវីដេអូបន្ទាប់ចាប់ផ្តើមផ្ទុកតែបន្ទាប់ពីវីដេអូកំពុងមើលរួចរាល់
3. ឯកសារវីដេអូជាច្រើនមាន "សន្ទស្សន៍" (moov) នៅចុងឯកសារ ដូច្នេះ browser ត្រូវទាញយកស្ទើរទាំងមូលមុនចាក់បាន
4. Feed វាស់ទីតាំងវីដេអូទាំងអស់រាល់ពេលអូស

**អ្វីដែលបានកែ**
- **Feed**៖ placeholder ពណ៌ប្រផេះស្រាល, បង្ហាញរូបទី 1 មុន, fade-in, spinner បង្ហាញតែពេលវីដេអូជាប់ពិតៗ (រង់ចាំ 0.35 វិនាទីមុន), ទុកវីដេអូ 2 ខាងលើ + 3 ខាងក្រោមឱ្យរួចរាល់ជានិច្ច (អូសត្រឡប់ក្រោយភ្លាម), វាស់តែវីដេអូជិតៗ
- **Profile**៖ វីដេអូចាក់ស្វ័យប្រវត្តិ (ស្ងាត់) ពេលឃើញ ≥ 60%, ផ្អាកពេលអូសចេញ, ចាក់តែមួយក្នុងពេលតែមួយ, ផ្ទុកតែវីដេអូនៅជិត (ជួយសន្សំទិន្នន័យ), រក្សាជម្រើសសំឡេងដូច Feed
- **ផ្ទុកឡើង (upload.html និង Feed composer)**៖ បន្ថែមជំហាន "fast start" ដាក់សន្ទស្សន៍នៅមុខឯកសារ (មិនបង្ហាប់ឡើងវិញ, គុណភាពដដែល) និងបន្ថយ bitrate

| រយៈពេល | Bitrate ចាស់ | Bitrate ថ្មី | ប្រហែលក្នុង 1 នាទី |
|---|---|---|---|
| ≤ 1 នាទី | 2.4 Mbps | 1.6 Mbps | ~12 MB |
| 1–5 នាទី | 1.8 Mbps | 1.2 Mbps | ~9 MB |
| > 5 នាទី | 1.35 Mbps | 0.9 Mbps | ~7 MB |
- ចាប់ផ្តើមបង្ហាប់ចាប់ពី > 8 MB (ពីមុន 12 MB), សំឡេង 96 kbps, គុណភាព 720p
- ចង់តូចជាងនេះ កាត់លេខ `VIDEO_KBPS_*` នៅក្នុង `upload.html` និង `feed.html` (ចង់ច្បាស់ជាងនេះ បង្កើនលេខ)

**ជំហានបន្ថែមក្នុង Cloudflare (មិនត្រូវការកូដ, ធ្វើឱ្យលឿនជាង)**

**ត្រូវដឹង**
- វីដេអូ **ចាស់** មិនត្រូវបានកែទេ មានតែវីដេអូ **ដែលបង្ហោះថ្មី** ទទួលបាន fast start និងទំហំតូចជាង

- វីដេអូពី iPhone ជា HEVC អាចចាក់មិនបានលើ Android/Chrome មួយចំនួន
- ខ្ញុំបានសាកល្បងតក្កវិជ្ជា (សាកល្បងលើវីដេអូពិតសម្រាប់ fast start, និងការចាត់ទុកក្លែងក្លាយសម្រាប់ការអូស) **ប៉ុន្តែមិនបានសាកល្បងលើ browser ទូរស័ព្ទពិតទេ**

## ✉️ ផ្ទៀងផ្ទាត់អ៊ីមែល (លេខកូដ 6 ខ្ទង់) មុនបង្កើតគណនី

3. បន្ទាប់ពីលេខកូដត្រឹមត្រូវ ទើបបន្តទៅជំហានទី 2 ហើយបង្កើតគណនី (Server ពិនិត្យ "ភស្តុតាង" ដែលបានចុះហត្ថលេខា 30 នាទី ដែលចងជាប់នឹងអ៊ីមែលនោះ មិនអាចបង្កើតគណនីបានបើគ្មានវា)

**ច្បាប់សុវត្ថិភាព**
- លេខកូដមានសុពលភាព 10 នាទី, ខុស 5 ដង → លេខកូដត្រូវបិទ, ផ្ញើម្តងទៀតបានរៀងរាល់ 60 វិនាទី, អតិបរមា 5 លេខកូដ/ម៉ោង/អ៊ីមែល
- កំណត់ក្នុង 1 IP, ហើយមានការកំណត់ចំនួនអ៊ីមែលក្នុងមួយថ្ងៃ (`EMAIL_DAILY_LIMIT`, លំនាំដើម 90) ដើម្បីកុំឱ្យលើសកំណត់ឥតគិតថ្លៃនៃសេវា
- Server រក្សាទុកតែ "hash" នៃលេខកូដ មិនរក្សាទុកលេខកូដពិតទេ
- CAPTCHA ត្រូវបានផ្លាស់ទៅជំហានទី 1 (ការពារប៊ូតុងផ្ញើលេខកូដ) ។ "ផ្ញើម្តងទៀត" មិនត្រូវការ CAPTCHA ទេ ប៉ុន្តែប្រើបានតែចំពោះអ៊ីមែលដែលបានឆ្លងកាត់ CAPTCHA ក្នុង 30 នាទីចុងក្រោយ
- ការចុះឈ្មោះដោយលេខទូរស័ព្ទលែងអាចទៀតហើយ (ត្រូវការអ៊ីមែល) គណនីចាស់មិនប៉ះពាល់

**⚠️ ហេតុអ្វីមិនប្រើ Gmail ផ្ទាល់ដើម្បីផ្ញើ**
Render ឥតគិតថ្លៃ **បិទការផ្ញើអ៊ីមែលតាម SMTP** (ច្រក 25, 465, 587) តាំងពី 26 កញ្ញា 2025 ដូច្នេះ Gmail SMTP មិនអាចប្រើបានទេ (ហើយ Gmail ធម្មតាមានកំណត់ ~500/ថ្ងៃ)។ ដូច្នេះប្រើសេវាផ្ញើតាម HTTPS ជំនួស (Resend ឬ Brevo)។ **អ្នកទទួលអាចប្រើ Gmail ឬអ៊ីមែលណាក៏បាន** គ្រាន់តែអ្នកផ្ញើជាអាសយដ្ឋាន `no-reply@camfeedkh.com`។

**ជម្រើសសេវាផ្ញើ (កំណត់ឥតគិតថ្លៃ, ពិនិត្យតម្លៃបច្ចុប្បន្ននៅគេហទំព័ររបស់ពួកគេ)**
| សេវា | ឥតគិតថ្លៃ | ចំណាំ |
|---|---|---|
| **Resend** (ណែនាំ) | 100 អ៊ីមែល/ថ្ងៃ, 3,000/ខែ | ត្រូវផ្ទៀងផ្ទាត់ដែន camfeedkh.com ទើបផ្ញើទៅអ្នកណាក៏បាន |
| Brevo | 300 អ៊ីមែល/ថ្ងៃ | ត្រូវផ្ទៀងផ្ទាត់អ្នកផ្ញើ (ឬដែន) ហើយមាន "Sent with Brevo" ក្នុងអ៊ីមែល |

**ជំហានដំឡើង Resend**
1. resend.com → ចុះឈ្មោះ
2. Domains → Add Domain → `camfeedkh.com`
3. Resend បង្ហាញ DNS records (SPF, DKIM...) → ចូល Cloudflare → ដែនរបស់អ្នក → DNS → Records → បន្ថែមតាមតម្លៃដែលពួកគេផ្តល់ (ប្រភេទ CNAME ដាក់ "DNS only" ពពកប្រផេះ) → រង់ចាំស្ថានភាព **Verified**
4. API Keys → Create API Key (Sending access) → ចម្លងសោ (ចាប់ផ្តើមដោយ `re_`)
5. Render → Environment → បន្ថែម៖
   - `EMAIL_PROVIDER` = `resend`
   - `RESEND_API_KEY` = សោរបស់អ្នក
   - `EMAIL_FROM` = `CamFeed <no-reply@camfeedkh.com>`
   - (ស្រេចចិត្ត) `EMAIL_DAILY_LIMIT` = `90` (ប្រើ `280` បើជា Brevo)
   
   សម្រាប់ Brevo៖ `EMAIL_PROVIDER=brevo`, `BREVO_API_KEY=...`, `EMAIL_FROM` = អ្នកផ្ញើដែលបានផ្ទៀងផ្ទាត់ក្នុង Brevo
6. ជំនួស/បន្ថែមឯកសារ៖ ថតមេ៖ `server.js`, `auth.js`, **`mailer.js` (ថ្មី)**, **`signup-verification.js` (ថ្មី)** · ថត `public`៖ `index.html`

**ស្ថានភាពមុនដំឡើងសេវា email៖** បើអ្នកមិនទាន់ដាក់ `EMAIL_PROVIDER` ទេ ការចុះឈ្មោះនៅតែដំណើរការដូចមុន (ដោយ CAPTCHA) ហើយ Render Logs បង្ហាញ `[mailer] E-mail is not configured`។ ពេលដាក់ត្រូវហើយ ការផ្ទៀងផ្ទាត់ចាប់ផ្តើមដោយស្វ័យប្រវត្តិ។

**សាកល្បង**៖ ចុះឈ្មោះដោយ Gmail របស់អ្នកផ្ទាល់ ពិនិត្យប្រអប់សំបុត្រ (និង Spam) ត្រូវមានអ៊ីមែល "CamFeed: 123456"។ ខ្ញុំបានសាកល្បងតក្កវិជ្ជាដោយ database និងសេវា email ក្លែងក្លាយ **មិនទាន់បានសាកល្បងជាមួយ Resend/Brevo ពិតប្រាកដទេ**។

**ជំហានដំឡើង**
1. ចូល **gateway.telegram.org** ដោយលេខទូរស័ព្ទ Telegram របស់អ្នក → ទទួលបាន **API access token**
2. បញ្ចូលក្រេឌីត (ត្រូវទូទាត់តាម Fragment ដែលជាធម្មតាប្រើ cryptocurrency) តម្លៃក្នុងមួយលេខកូដបង្ហាញក្នុង Gateway (Telegram ប្រកាសប្រហែល $0.01) លេខកូដដែលមិនដល់ត្រូវសងស្វ័យប្រវត្តិ
3. **សាកល្បងដោយលេខទូរស័ព្ទផ្ទាល់ខ្លួនអ្នក ឥតគិតថ្លៃជានិច្ច**
4. Render → Environment បន្ថែម៖
   - `TELEGRAM_GATEWAY_TOKEN` = access token (សម្ងាត់)
   - (ស្រេចចិត្ត) `TELEGRAM_GATEWAY_SENDER` = ឈ្មោះ Channel ដែល Telegram បានផ្ទៀងផ្ទាត់ ដើម្បីបង្ហាញឈ្មោះក្រុមហ៊ុន (បើគ្មាន សារមកពី "Verification Codes")
   - (ស្រេចចិត្ត) `TELEGRAM_GATEWAY_TTL` (វិនាទី 30-3600, លំនាំដើម 300) និង `GATEWAY_DAILY_LIMIT`
5. ឯកសារថ្មី (ថតមេ)៖ **`telegram-gateway.js`**, **`phone-verification.js`** · ជំនួសថតមេ៖ `server.js`, `auth.js`, `telegram-login.js` · ជំនួសថត public៖ `index.html`, `settings.html`

**ត្រូវដឹង**
- ខ្ញុំបានសាកល្បងដោយ Gateway ក្លែងក្លាយ **មិនទាន់បានសាកល្បងជាមួយ Telegram Gateway ពិត ឬ Fragment ទេ** ឈ្មោះកំហុសពិតរបស់ Gateway ខ្ញុំដោះស្រាយជាសារទូទៅ ("ប្រើ Gmail ជំនួស")
- តារាងថ្មី `phone_verifications` បង្កើតដោយស្វ័យប្រវត្តិ
- ប្រសិនបើអ្នកចង់ឱ្យទម្រង់តម្រូវ **ទាំងលេខទូរស័ព្ទ និង Gmail** (មិនមែនជ្រើសមួយ) សូមប្រាប់ ខ្ញុំអាចកែ
